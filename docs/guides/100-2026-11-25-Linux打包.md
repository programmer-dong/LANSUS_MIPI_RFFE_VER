# Linux 程序包

界面程序打成两个目录包：CentOS 7 x86_64 和 Rocky Linux 8 x86_64。构建在对应的基础镜像里完成，产物互不通用。

工作流文件已在仓库中。目标系统上的窗口还没有验收。

## 构建内容

| 目标 | 基础镜像 | 产物 |
|---|---|---|
| CentOS 7 x86_64 | `ghcr.io/lansus-filter/lansus-centos7-base:latest` | `dist/linux/centos7-x86_64/mipi_gui/` |
| Rocky Linux 8 x86_64 | `ghcr.io/lansus-filter/lansus-rocky-linux8-base:latest` | `dist/linux/rocky-linux8-x86_64/mipi_gui/` |

共享 spec 是 `build/linux/common/mipi_gui.spec`。脚本通过 `LANSUS_BUILD_TARGET` 指定 `centos7` 或 `rocky8`，其他值会失败。这是 tkinter 界面，不收集 PySide。

解释器是 uv 安装的 CPython 3.11.18。uv 版本是 0.13.10。容器里使用官方 musl 构建的 uv，避免 CentOS 7 的 glibc 2.17 带不动较新的 gnu 版 uv。

## 依赖

| 包 | 版本 | 用途 | 许可与核查 |
|---|---|---|---|
| numpy | 2.2.6 | pandas 的数组库 | 团队白名单。2.3 起不再提供 glibc 2.17 的 wheel，因此固定此版本 |
| pandas | 2.2.3 | 读取寄存器表 | 团队白名单。保留 glibc 2.17 的 wheel |
| openpyxl | 3.1.5 | 读取 xlsx | 团队白名单 |
| xlrd | 2.0.2 | 读取 xls | BSD。PyPI 上传时间 2025-06-14。2026-11-25 查询 OSV，该包没有漏洞记录 |
| pyinstaller | 6.22.3 | 打包，开发依赖 | 团队白名单 |

锁文件是 `uv.lock`。NumPy 和 pandas 的 Linux x86_64 wheel 标签是 `manylinux_2_17`。

## 用 GitHub Actions 构建

1. 在仓库 **Settings → Secrets and variables → Actions** 添加 `GHCR_USERNAME` 和 `GHCR_TOKEN`。令牌需要能读取上面两个镜像。
2. 把包含这些构建文件的提交推到 GitHub。
3. 用下面任一方式启动 `.github/workflows/linux-packaging.yml`：
   - Actions 页面选择该工作流，执行 **Run workflow**。
   - 推送标签 `v主版本.次版本.修订号`，例如 `v1.0.0`。
4. 运行成功后，在该次运行的 Artifacts 下载候选包。保留 14 天。

候选包里有：

```text
centos-7/mipi_gui.tar
rocky-linux8/mipi_gui.tar
SHA256SUMS
```

压缩包保留目录模式里的符号链接。在对应系统解压后运行 `mipi_gui/mipi_gui`。

Actions 成功只说明镜像里打出了文件。还要在干净的 CentOS 7 或 Rocky Linux 8 上检查：

```bash
tar -xf mipi_gui.tar
file mipi_gui/mipi_gui
ldd mipi_gui/mipi_gui
./mipi_gui/mipi_gui
```

目标机器需要图形界面，以及 `libX11`、`libXext`、`libXrender`。打开窗口后按使用说明选择寄存器表并生成激励。

## 本机 Podman

在 Linux 上也可以不经过 Actions，用本机 Podman 按工作流里的顺序执行：拉取指定镜像、以仓库根目录为上下文构建对应 Dockerfile、挂载 `dist/linux/<目标>/` 后运行容器。不要改用其他基础镜像，也不要在宿主机上用系统 Python 直接调用 PyInstaller。
